# 风险与发布指南

> 本文不是法律意见，只是项目发布前的风险控制清单。正式商业化或大规模分发前，建议咨询专业律师。

## 1. 项目定位

推荐定位：

> Douban Archive 是一个本地优先的个人数据归档工具，帮助用户导出自己登录后本来可以访问的豆瓣内容。

不推荐定位：

- 豆瓣爬虫
- 绕过风控工具
- 批量采集工具
- 数据抓取神器

## 2. 合规边界

项目应坚持以下边界：

- 只导出用户自己的数据。
- 只读取用户登录后本来可以手动访问的页面。
- 不绕过验证码、登录、权限、风控或付费限制。
- 不抓取其他用户的隐私内容。
- 不向第三方服务器上传导出数据。
- 不公开用户导出的真实数据样本。
- 不使用豆瓣商标暗示官方合作或授权。

## 3. 数据归属与风险理解

个人通常对自己发布的内容、评分、短评、日记等享有相应权益，也对自己的个人信息享有查阅、复制等权利。

但这不等于可以无限制使用平台系统、接口、页面结构或他人内容。平台协议通常还会约束账号使用、系统访问、知识产权、商标、内容传播和异常访问行为。

因此这个项目的合理表达应该是：

> 帮助用户备份自己的个人记录，而不是替代平台、攻击平台或批量采集平台数据。

## 4. GitHub 发布前清单

发布到 GitHub 前，确认不要提交：

- `.pem` 私钥文件
- `.crx` 打包文件
- 真实导出的豆瓣数据
- 含有个人信息的截图
- Cookie、token、密码
- 浏览器配置文件
- 调试日志

建议提交：

- `README.md`
- `README.zh-CN.md`
- `PRIVACY.md`
- `SECURITY.md`
- `LICENSE`
- `docs/zh-CN/USER_GUIDE.md`
- `docs/en/USER_GUIDE.md`
- 匿名化示例数据

## 5. 私钥、公钥与插件打包

简单理解：

- 私钥：只能自己保存，不能公开。别人拿到私钥，可能冒充你发布同一个扩展。
- 公钥：可以公开，用来验证签名。
- `.pem`：Chrome 扩展打包时可能生成的私钥文件，不要上传到 GitHub。
- `.crx`：打包后的扩展文件，不建议和源码一起提交；后续可以放到 GitHub Releases。

## 6. 推荐发布流程

1. 先发布源码仓库，不急着发 Chrome Web Store。
2. 仓库里只放 `extension/` 源码和文档。
3. 本地保管 `.pem`，不要提交。
4. 使用 GitHub Release 发布版本说明。
5. 如果要附带 `.crx`，放到 Release，不放进源码目录。
6. 每次发布前检查权限、隐私说明和更新日志。

## 7. 推荐传播话术

推荐说法：

- 本地优先
- 个人数据归档
- 数据主权
- 备份自己的数字记忆
- 为未来 AI 个人助手准备结构化数据

避免说法：

- 破解
- 反爬绕过
- 批量抓取
- 爬全站
- 无视限制

## 8. 和 AI 结合时的风险

导出数据给 AI 使用前，用户应确认：

- 是否包含隐私日记
- 是否包含他人姓名、联系方式或聊天内容
- 是否会上传到第三方 AI 服务
- 是否需要先做脱敏
- 是否只在本地模型中使用

默认建议：

> JSON 作为主备份，Markdown 用于阅读，Excel CSV 用于表格分析。涉及隐私内容时，先本地保存，不要随意上传。
